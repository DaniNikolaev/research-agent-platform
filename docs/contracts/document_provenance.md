# Модель происхождения (provenance) в конвейере документов

**Модули:** `domain/documents/elements.py`, `domain/documents/provenance.py`,
`platform/document_parsing/docling/converters.py`, `platform/document_parsing/pymupdf/pdf_inspector.py` ·
**Итерация:** 2

Происхождение — это ответ на вопрос «откуда взялся этот фрагмент и где он находится в источнике».
Модель строится на трёх независимых опорах: **физическая страница**, **порядок чтения** и
**символьный диапазон в каноническом тексте**; геометрия (`bbox`) — четвёртая, необязательная.

Главное правило: **всё, чего парсер не сообщил, остаётся `null`.** Придуманная страница,
придуманный диапазон или придуманный прямоугольник хуже отсутствующего: отсутствие видно, а
выдумка выглядит как факт.

---

## 1. Физическая страница

| Правило | Как обеспечено |
|---|---|
| `page_number` — физическая страница источника, 1-based | `PageRecord.page_number ≥ 1`; для PDF набор страниц строится из таблицы страниц документа |
| Полнота последовательности | валидатор `ParsedDocument` требует ровно `1..N` без пропусков; страница без единого блока всё равно создаётся (`status=empty`) |
| Колонцифра не подменяет номер | номер страницы берётся из `prov.page_no` парсера, а не из текста; текст «247» остаётся текстом |
| У TXT страниц нет | `page_number = null`, `page_count = null`, `pages = []`; валидатор запрещает изобретать «страницу 1» |
| Блок без провенанса не приписывается странице | `page_number` берётся из `prov[0].page_no`; если провенанса нет — остаётся `null` |

Следствие: у PDF, где часть элементов не имеет провенанса, появятся элементы с
`page_number = null`. Quality Gate реагирует на это проверкой `structure_page_provenance`
(предупреждение уровня `major`), а не молчанием.

## 2. Порядок чтения

`reading_order` — **детерминированная позиция внутри документа**, а не утверждение о том, как
парсер обходил дерево. В Итерации 2:

* Docling: порядковый номер элемента в `document.iterate_items()` (0, 1, 2, …); таблицы и
  подписи рисунков участвуют в нумерации, поэтому возможны «дыры» в нумерации элементов;
* TXT-адаптер: порядок появления блока в тексте (0, 1, 2, …), без дыр;
* PyMuPDF-fallback: одна страница — один блок, номер страницы по порядку.

Инварианты:

1. `reading_order ≥ 0`;
2. в документе нет двух элементов с одинаковым `reading_order` (проверка
   `structure_reading_order_unique`, провал уровня `major`);
3. канонический текст собирается сортировкой по `reading_order`, поэтому порядок блоков в тексте и
   в модели совпадает по построению.

## 3. Система координат

Нормализованная система Итерации 2 (значение по умолчанию для `BBox`):

| Свойство | Значение |
|---|---|
| единица | PDF points (`pt`), 1/72 дюйма |
| начало координат | левый верхний угол страницы (`top_left`) |
| оси | `x` вправо, `y` вниз |
| размеры страницы | `page_width`, `page_height` в тех же единицах |
| допуск | 2.0 единицы за границу страницы |

`BBox` — типизированная величина, а не четыре числа:

* `unit = unknown` + `origin = unknown` + `system = "<имя системы>"` означает «парсер не может
  выразить свою систему»; такие координаты можно показать, но нельзя сравнивать с нормализованными;
* если `unit` объявлен, `page_width`/`page_height` обязательны;
* `x0 ≤ x1`, `y0 ≤ y1`;
* выход за страницу больше допуска отвергается валидатором (и дополнительно проверяется Quality
  Gate как предупреждение).

### 3.1. Перевод из Docling

Docling сообщает `l/t/r/b` с **нижним левым** началом. Адаптер
(`normalise_bbox`) выполняет:

1. нормализацию порядка краёв (`l/r` и `t/b` при необходимости меняются местами);
2. определение системы по `coord_origin`:
   * содержит `BOTTOM` → `y0 = page_height - t`, `y1 = page_height - b`, затем
     `min/max` (верхнее левое начало, PDF points);
   * `TOPLEFT` или origin не указан → координаты уже идут сверху, `y0 = min(t, b)`,
     `y1 = max(t, b)`;
3. если высота страницы неизвестна → `unit = unknown`, `origin = unknown`,
   `system = "docling/<origin>"`, координаты сохраняются как есть.

### 3.2. Поворот страницы

Контракт требует, чтобы фрейм следовал повороту так, как страница отрендерена, и `PageRecord`
несёт `rotation`. В Итерации 2:

* `PyMuPDFInspector` сообщает `rotation` и размеры `page.rect` (видимые, то есть с учётом поворота);
* Docling-адаптер берёт размеры из таблицы страниц Docling и **`rotation` не заполняет** (остаётся
  `0`);
* поведение на реальных PDF с ненулевым поворотом (`/Rotate`) **не проверялось** — тестовых
  фикстур с поворотом нет.

Поэтому утверждение «bbox поворот-осознан» верно на уровне контракта и реализации инспектора, но
не подтверждено экспериментом для Docling-ветки.

## 4. `block_id`

`block_id` — детерминированный, но **не глобально стабильный** идентификатор. Он вычисляется как
первые 16 hex SHA-256 от строки-кортежа, поэтому одинаковый вход даёт одинаковый id.

| Источник | Формула | Стабилен между запусками |
|---|---|---|
| Docling | `document_id \| run_id \| reading_order \| element_type \| page_number \| text[:200]` | **нет** — `run_id` входит в хеш |
| TXT | `document_id \| reading_order \| element_type \| line_start \| text[:200]` | да (при том же разборе) |
| PyMuPDF-fallback | `document_id \| page_number \| text[:200]` | да |

Практические следствия:

* `block_id` уникален внутри документа и запуска (валидатор `ParsedDocument` это проверяет);
* повторная обработка того же PDF в новом запуске даёт **другие** `block_id`;
* `block_id` **не** является адресом для evidence: адрес фрагмента — `document_id` + `run_id` +
  `char_start`/`char_end` канонического текста;
* если в Итерации 3+ потребуется сквозная стабильность `block_id` между запусками, это будет
  изменение схемы (и, вероятно, новая версия контракта) — сейчас её нет.

## 5. Символьные диапазоны

`char_start`/`char_end` адресуют канонический текст:

* вычисляются **во время сборки** текста (`DocumentParsingService._canonicalize`), а не парсером;
* Docling-адаптер и TXT-адаптер диапазонов не заполняют вовсе — в их payload поля `null`;
* 0-based, конец не включается, единица — Unicode code points;
* инвариант `canonical_text[char_start:char_end] == element.text` проверяется Quality Gate;
* диапазоны действительны только для версии канонизации, записанной в
  `canonical_text.canonicalization_version`.

Почему не байты: байтовые смещения ломаются при любой нормализации и зависят от кодировки; code
points переживают хранение в UTF-8 и сравнение строк.

## 6. Чего нельзя изобретать

| Нельзя | Почему | Что делается вместо |
|---|---|---|
| номер страницы для TXT | у текстового источника пагинации нет | `page_number = null`; валидатор и Quality Gate это требуют |
| «страницу 1» для документа без страниц | downstream не отличит выдумку от факта | `page_count = null`, `pages = []` |
| пропущенные физические страницы | разрыв последовательности скрывает потерю листов | страницы создаются из таблицы страниц, а не из найденных блоков |
| координаты в чужой системе, выданные за PDF points | прямоугольник без единиц и начала координат нельзя сравнить | `unit = unknown` + `system` |
| символьные диапазоны «по догадке» | они перестанут воспроизводить текст | диапазоны считаются при сборке; при невозможности — `null` |
| текст для страницы, ушедшей в OCR | OCR-движка нет | `text = ""`, статус `ocr_required`, номер страницы в `ocr_required_pages` |
| уровень заголовка, которого нет | иерархия — утверждение о структуре | Docling: `item.level` или глубина вложенности, ограниченная 1..6; TXT: всегда 1 с `confidence = 0.6` |
| ячейки таблицы, которых не было | таблица — структура, а не текст | `cells = []`, `extraction_status = empty`, проверка `tables_structure` |
| подпись рисунка, если её нет | подпись — отдельный элемент | `caption = null` |

## 7. Диагностика PyMuPDF против провенанса Docling

Два источника данных отвечают на разные вопросы и **не заменяют** друг друга.

| Вопрос | PyMuPDF (`PyMuPDFInspector`) | Docling (`DoclingPdfParser`) |
|---|---|---|
| Сколько физических страниц в файле? | да, `page_count` (используется как эталон в `structure_page_count_matches_source`) | да, из таблицы страниц |
| Файл зашифрован / повреждён? | да, `is_encrypted`, `is_corrupt` (на этапе приёма) | нет (до разбора дело не доходит) |
| Есть ли на странице родной текстовый слой? | да, `has_native_text` порогом `MIN_NATIVE_TEXT_CHARS = 20` | косвенно: есть ли текст |
| Сколько символов родного текста? | да, `text_char_count` | нет отдельного счётчика |
| Сколько изображений и какую площадь занимают? | да, `image_count`, `image_area_ratio` | нет |
| Поворот страницы? | да, `rotation` | не заполняется |
| Где именно находится блок (bbox)? | **нет** | да, с переводом в PDF points / top-left |
| К какому разделу относится блок? | **нет** | да, через стек заголовков |
| Таблицы структурированы? | **нет** | да, через TableFormer |
| Что делать, если Docling упал технически? | да: плоский текст постранично (`extract_text_fallback`) | — |

Правила совместного использования:

1. инспекция выполняется **на этапе приёма** и служит эталоном количества страниц и признаком
   сканированных страниц;
2. результат инспекции передаётся в Quality Gate как независимый источник фактов
   (`DocumentInspection`);
3. fallback-текст PyMuPDF создаёт элементы с `source = pymupdf_fallback`, **без** `bbox`, **без**
   таблиц и **без** разделов; результат помечается `parsing_status = parsed_with_fallback`, а Gate
   выносит `fallback_parse_requires_review` (`failed`, `major`) → `needs_human_review`;
4. инспектор никогда не подменяет структурный парсер: он либо поставляет диагностику, либо
   аварийный плоский текст.

## 8. Сводка полей провенанса по типам элементов

| Тип | `page_number` | `bbox` | `reading_order` | `char_*` | `section_id` | `source` |
|---|---|---|---|---|---|---|
| Docling-элемент | из `prov.page_no` или `null` | из `prov.bbox` (перевод) | индекс обхода | из канонизации | из стека заголовков | `docling` |
| Таблица | как у элемента | как у элемента | индекс обхода | из канонизации | из стека | `docling` |
| Рисунок без подписи | как у элемента | как у элемента | индекс обхода | **нет** (элемента нет) | из стека | `docling` |
| TXT-блок | `null` | `null` | порядок блока | из канонизации | `null` | `txt_decoder` |
| Fallback-блок | номер страницы | `null` | порядок блока | из канонизации | `null` | `pymupdf_fallback` |
