# ADR-007. Условный выбор full-context, RAG или hybrid для Agent 1A

- **Статус:** Accepted (контракт режимов и стратегии) / Deferred (chunking, embeddings и retrieval — Итерация 4)
- **Дата:** 2026-11-12
- **Связанные требования ТЗ:** режимы извлечения и критерий выбора; запрет cross-document retrieval;
  правило «пустой retrieval не означает not_found»
- **Связанные разделы ADD:** §10.1–§10.6, §22 (этап 4), §27 п. 4, §27 п. 5

## Контекст

ADD §10.1 ограничивает retrieval поиском внутри конкретной статьи и запрещает подмешивать другие
публикации при заполнении карточки; поиск жёстко фильтруется по `document_id` и версии файла.
ADD §10.2 требует решать режим по токенам конкретного tokenizer/model profile, а не по числу символов,
и допускает `HYBRID`. ADD §10.5 запрещает выводить `not_found` из пустого retrieval: нужен coverage
trail из повторных запросов, lexical search по синонимам, проверок разделов и расширенного поиска.

Ранее контракт знал только `full_context`, `rag` и `not_applicable`: `HYBRID` из ADD §10.2 не был
представлен, а способ предъявления документа модели и способ поиска были смешаны в одном поле.
Коррективный обзор закрыл вопрос: в контракте 2.1 четыре режима и отдельная стратегия поиска.
Chunking, embeddings, индекс, retrieval и reranking не реализованы — это Итерация 4.

## Решение

1. **Два независимых понятия.** `RetrievalMode` (`full_context`, `rag`, `hybrid`, `not_applicable`)
   отвечает на вопрос «что получает модель»; `RetrievalStrategy` (`dense`, `lexical`, `dense_lexical`) —
   «как искали фрагменты». Объединять их в один enum нельзя: одинаковый режим может использовать разные
   стратегии, и наоборот.

2. **Семантика режимов.**
   - `full_context` — весь нормализованный текст статьи в вычисленном бюджете, который до отправки
     учитывает системный промпт, резерв на output, технический резерв и возможности конкретной модели;
     молчаливое усечение запрещено (ADR-005).
   - `rag` — найденные фрагменты плюс необходимый соседний контекст с page/section/provenance.
   - `hybrid` — короткий глобальный контекст документа (библиография, аннотация, карта разделов,
     структурные факты) **плюс** целевые фрагменты; это явно не способ протолкнуть полную длинную
     статью за лимит контекста.
   - `not_applicable` — retrieval для данной операции не требуется.

3. **Режим выбирает детерминированная политика Python, а не LLM.** Решение принимается по фактическим
   подсчётам токенов, доступному контексту модели, структуре документа, конфигурации обработки и тому,
   какие разделы обязаны быть просмотрены. Модель не участвует в выборе режима и не может его изменить.
   В Итерации 0 реализованы enum, поля и контрактные инварианты; политика и tokenizer — Итерация 4.

4. **Безопасный откат при неизвестной токенизации или возможностях модели.** Если бюджет нельзя
   вычислить достоверно, политика не объявляет поисковый режим: остаются `full_context` для заведомо
   помещающегося текста или `not_applicable`, если retrieval не нужен. Контракт делает откат
   проверяемым: для `rag`/`hybrid` обязательны `embedding_model_id`, `index_version` и
   `retrieval_strategy`, а для `full_context`/`not_applicable` все три поля должны быть `None`
   (`RunMetadata._retrieval_provenance_is_complete`, `FieldCoverageRecord._strategy_matches_mode`).

5. **Влияние на контракты.**

   | Элемент | Изменение в контракте 2.1 |
   |---|---|
   | `RetrievalMode` | добавлен `hybrid`; всего четыре значения |
   | `RetrievalStrategy` | новый enum: `dense`, `lexical`, `dense_lexical` |
   | `RunMetadata.retrieval_strategy` | обязателен для `rag`/`hybrid`, запрещён для остальных режимов |
   | `FieldCoverageRecord.retrieval_mode/retrieval_strategy` | повторяют режим и стратегию прогона; стратегия обязательна только для поисковых режимов |
   | Agent 1A package 2.1 | `coverage_trail` на 27 полей; `not_found` — только при `complete` и `not_found_eligible`, а для `rag`/`hybrid` — ещё и при исполненном full-text fallback |
   | Agent 1B input 1.1 | принимает пакеты 2.0 и 2.1; `coverage.availability` различает `recorded` и `not_recorded` |
   | Схемы | `contracts/agent_1a/v2.1/…`, `contracts/agent_1b/v1.1/…`; замороженные 2.0/1.0 не меняются |

6. **`not_found` требует покрытия.** Для `rag`/`hybrid` он невозможен без исполненного full-text
   fallback, записанного как попытка, а не как флаг; вывод из низкого retrieval score запрещён.

7. **Reranker — необязателен** для первого релиза (ADD §10.4).

## Статус

Accepted. `HYBRID` из ADD §10.2 представлен в `RetrievalMode`, поэтому прежнее противоречие «ADD
требует hybrid, контракт его не знает» закрыто; режим и стратегия разделены, провенанс проверяется
кодом. Chunking, embeddings, индекс, retrieval, reranking и сама политика выбора — Итерация 4.
Выбор embedding-модели и необходимость reranker-а — решения владельца (OI-009, OI-010).

## Последствия

Положительные: по пакету видно, что получила модель и как искали фрагменты; смешение режимов и
стратегий между запусками не проходит валидацию; `hybrid` больше не требует обхода контракта.

Цена: сравнение прогонов обязано учитывать оба поля; RAG требует версий индекса и повторной
индексации при смене эмбеддингов (ADD §19.3 п. 6); `not_found` в поисковых режимах невозможен без
исполненного fallback.

## Альтернативы

- **Всегда RAG.** Отклонено: для короткой статьи индекс и поиск дороже полного контекста.
- **Всегда full context.** Отклонено: длинные PDF не помещаются в бюджет, усечение запрещено (ADR-005).
- **Один enum «режим + стратегия».** Отклонено: смешивает два вопроса и исключает `hybrid` с lexical.
- **Режим выбирает LLM.** Отклонено: выбор стал бы недетерминированным и неаудируемым.
- **`hybrid` как «полный текст плюс retrieval».** Отклонено: это обход бюджета, а не hybrid.

## Открытые риски

1. Политика выбора и tokenizer не реализованы: критерий режима не проверен ни на одном реальном PDF.
2. Embedding-модель и её revision не выбраны (OI-009), поэтому формат индекса и `dimensions` не зафиксированы.
3. Необходимость multilingual reranker-а не подтверждена (OI-010); качество `hybrid`/`rag` без него неизвестно.
4. Фактические лимиты контекста и выхода выбранной модели не подтверждены (OI-003); без них бюджет
   `full_context` и выбор режима остаются расчётной гипотезой.
5. Chunking, embeddings и retrieval не реализованы: поведение поиска на колонках, таблицах и
   OCR-страницах не наблюдалось.
