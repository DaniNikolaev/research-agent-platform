# ADR-010. Локальный CLI-first runtime как модульный монолит

- **Статус:** Accepted (Windows-native CLI-first) / Deferred (Linux/Docker, канал human review)
- **Дата:** 2026-11-12
- **Связанные требования ТЗ:** запуск через CLI; отсутствие зависимости от DSH; эксплуатационная
  модель первого этапа
- **Связанные разделы ADD:** §6.2, §20.1–§20.3, §22 (этап 0), §27 п. 2, §27 п. 9

## Контекст

ADD §20.1 описывает первый этап: Python-приложение запускается локально через CLI, PostgreSQL +
pgvector поднимаются через Docker Compose, Artifact Store — локальная директория с контролируемыми
путями, LLM вызывается через Model Gateway по API, один документ за запуск. ADD §20.2 относит FastAPI
к следующему этапу, ADD §20.3 запрещает добавлять Redis, очереди, отдельные сервисы и Kubernetes без
подтверждённой нагрузки.

В Итерации 0 runtime-команд нет по замыслу: `cli.py` предоставляет `--help`, `--version` и
`contracts validate`; команды `process`/`run-agent`/`parse` не создавались — команда, которая только
имитирует работу, хуже отсутствующей. Конфигурация слоистая: `config/application.example.yaml` и
`config/models.example.yaml` плюс четыре не-секретных переменных окружения, где DSN задаётся **именем**
переменной, а не значением.

## Решение

1. **Целевая платформа первого релиза — Windows 10 Pro 22H2 или совместимая более новая Windows.**
   Python 3.13.x (не ниже 3.13.18; в lock — 3.13.18, ADR-009), пакетный менеджер `uv`, CLI-first. Локальная разработка
   не требует обязательного Docker или WSL2; контейнеры остаются перспективным вариантом, а не
   обязательной инфраструктурой сейчас.

2. **Первая форма развёртывания — локальный CLI.** Один процесс, один документ за запуск,
   последовательная пакетная обработка 1–5 документов (ADD §20.1). Application layer один для CLI и
   будущего API.

3. **Код переносим между ОС.** В Domain и Application нет абсолютных Windows-путей: `source_file_name`
   обязан быть голым именем файла (без `/`, `\` и `:`), ссылки на артефакты — логические `artifact://`
   URI, а пути, создаваемые приложением, берутся из конфигурации и строятся через `pathlib`. Это
   проверяется контрактами (`DocumentManifest`, `parse_artifact_uri`) и AST-тестами границ.

4. **DSH не требуется в runtime.** Ни один модуль не импортирует DSH и не требует его сессии; CLI
   запускается обычным `uv run research-platform …` (ADR-001).

5. **Секреты — только через ссылки.** Конфигурация хранит `api_key_env` и `database_dsn_reference`, то
   есть имена переменных; коммит YAML-файла не может утечь credential.

6. **PostgreSQL — инфраструктура следующей итерации.** Локальная служба или Docker Compose — решение
   владельца (OI-006); отсутствие обязательного Docker не отменяет целевой PostgreSQL 18 + pgvector
   (ADR-006). Linux/Docker-развёртывание остаётся перспективой, а не требованием текущего этапа.

7. **Канал human review — Deferred.** Где пользователь утверждает `WARNING`/`CRITICAL` — CLI-подсказка
   или отдельный UI — решение владельца (OI-007). FastAPI как второй интерфейс — следующая итерация
   после стабилизации application layer.

## Статус

Accepted для Windows-native CLI-first: точка входа, конфигурация, запрет зависимости от DSH и
переносимость контрактов реализованы. Deferred: Linux/Docker-развёртывание (OI-006) и канал human
review (OI-007); FastAPI и Run Manager — Итерация 1 и далее. Checkpoint store (SQLite или PostgreSQL)
также не выбран.

## Последствия

Положительные: минимальная эксплуатационная поверхность; воспроизводимый локальный запуск без
контейнеров; конфигурация проверяема типами (`PlatformSettings`) и не содержит секретов; контракты
переносимы между Windows и Linux.

Цена: без API нет удалённого запуска, мониторинга статусов и внешнего UI; без обязательного Docker нет
воспроизводимой БД, поэтому Итерация 1 не сможет проверять миграции автоматически; привязка к
локальной файловой системе делает права и пути частью эксплуатации (ADD §16.4).

## Альтернативы

- **Container-first (Docker/WSL2 с первого дня).** Не выбрано сейчас: замедляет контрактный этап и
  требует Docker там, где он не обязателен; остаётся перспективным вариантом.
- **WSL2 как основная среда.** Отклонено для первого релиза: Windows-native проще для целевого
  пользователя; переносимость кода обеспечивается контрактами, а не средой.
- **FastAPI первым интерфейсом.** Отклонено: ADD §19.3 п. 5 и §20.2 — CLI запускает тот же application
  layer, API не является блокером первого релиза.
- **DSH-зависимый запуск или UI внутри DSH.** Отклонено: ADD §6.2 запрещает зависимость штатной
  обработки от DSH.

## Открытые риски

1. Docling и OCR на Windows и в контейнере ведут себя по-разному; воспроизводимость парсинга без
   проверки на целевой Windows-машине не гарантирована.
2. Канал human review не определён (OI-007): `processing_status="waiting_for_human"` зарезервирован,
   но ни один интерфейс его не выставляет.
3. Runtime-команд нет: сквозной сценарий «PDF → пакет» не запускался ни разу, эксплуатационная модель
   проверена только на уровне контрактов.
4. Проверка прав и защита файловой системы (ADD §16.4) не реализованы: Artifact Store отсутствует, а
   корень артефактов задан логическим URI `artifact://local/artifacts` без проверки доступа.
