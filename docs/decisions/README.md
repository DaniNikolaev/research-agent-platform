# Журнал архитектурных решений (ADR) — `research-agent-platform`

Журнал фиксирует решения, которые **уже приняты и реализованы** в Итерации 0, и честно отделяет их от
решений, которые ещё не приняты. Дата среза — 2026-11-12: после коррективного обзора закрыты вопросы
режима retrieval, целевого storage-бэкенда, платформы локального запуска и формы evidence-контракта.

Назначение журнала: дать ответ на вопрос «почему в репозитории сделано именно так» без чтения всего
ADD, и не дать отложенным вопросам превратиться в неявные допущения. ADR — не пересказ ADD: каждый
документ описывает конкретное состояние этого репозитория, ссылается на разделы ADD, где это уместно,
и называет владельца для всего, что осталось открытым.

**Статусы:** `Accepted` — решение действует и проверяется кодом или тестами; `Deferred` — решение
не принято или не реализовано в указанной части; если это выбор владельца, он помечен
`Needs owner decision`. `Proposed` зарезервирован для ещё не принятых решений и в текущем срезе не
используется.

**Нумерация.** Числа ADR-001…ADR-010 относятся к этому журналу и не совпадают с таблицей
`ADR-001…ADR-012` из ADD §25: там перечислены кандидаты в решения со статусом `Proposed`, здесь —
записи о фактически реализованном и явно отложенном. Один и тот же номер в двух документах может
означать разные решения; ориентируйтесь на журнал.

**Поле «Связанные требования ТЗ».** В метаданных ADR указаны темы требований ТЗ, а не номера пунктов:
текст ТЗ не хранится в репозитории, и выдумывать номера пунктов было бы хуже, чем назвать требование
по смыслу. Номера проставляются владельцем при сверке с ТЗ.

| [ADR-002](ADR-002-modular-monolith.md) | Modular monolith | Accepted | Один Python-пакет и один процесс; агенты изолированы версионированными контрактами и Artifact Store, а не сетью |

| [ADR-004](ADR-004-agent-contracts-and-versioning.md) | Контракты агентов и версионирование | Accepted | Текущие контракты — 2.1/1.1, замороженные — 2.0/1.0; Pydantic — источник истины, заморозка подтверждена контрольными суммами; научный вердикт есть только у Agent 1B |
| [ADR-005](ADR-005-model-gateway.md) | Model Gateway | Accepted (интерфейс) / Deferred (адаптер) | Единый gateway с явными capability и нормализованными ошибками; первый кандидат — DeepSeek V4.1 Flash 1017, реквизиты и capability не подтверждены |
| [ADR-006](ADR-006-document-and-artifact-storage.md) | Хранение документов и артефактов | Accepted (архитектура) / Deferred (эксплуатация) | PostgreSQL 18 + pgvector — целевое хранилище метаданных; крупные артефакты — файловый store за портом, S3-совместимый позже |
| [ADR-007](ADR-007-agent1a-retrieval-strategy.md) | Retrieval-стратегия Agent 1A | Accepted | `RetrievalMode` и `RetrievalStrategy` — разные понятия; режим выбирает детерминированная политика Python, не LLM; `hybrid` представлен |
| [ADR-008](ADR-008-evidence-provenance.md) | Провенанс evidence | Accepted (контракт) / Deferred (резолвер) | Кандидат несёт только цитату и подсказки; `quote_occurrence` удалён, координаты и статус — у Python; `ambiguous` — полноценный исход |
| [ADR-009](ADR-009-dependency-baseline.md) | Базовая линия зависимостей | Accepted | Python 3.13.18, uv 0.13.7, точные пины, группы `dev`/`parsing`/`storage`/`api`; полный `langchain` не устанавливается |
| [ADR-010](ADR-010-runtime-deployment.md) | Runtime и развёртывание | Accepted (Windows-native CLI-first) / Deferred (Linux/Docker, HITL) | Windows 10 Pro 22H2+, Python 3.13.x, uv, CLI-first без обязательного Docker; Linux/Docker и канал human review отложены |

## Открытые вопросы

Открытые вопросы ведутся в [open_items.md](open_items.md). Это полный реестр решений, которые может
принять только владелец; таблица ниже — краткая выжимка, идентификаторы `OI-…` ведут в реестр.

| Открытый вопрос | Что именно не решено | Где закрывается | Основание |
|---|---|---|---|
| LLM-агрегатор и модель | имя и протокол агрегатора, capability, лимиты, эффективный model id | `OI-001`–`OI-005`; до выхода из Итерации 1 | ADD §27 п. 1; ADR-005 |
| Локальный PostgreSQL и backup | Docker Compose против локальной службы; политика резервного копирования | `OI-006`; Итерация 1 | ADD §27 п. 7; ADR-006, ADR-010 |
| Канал human review | CLI-подсказка против отдельного UI для утверждения quality gate | `OI-007`; Итерация 2–3 | ADD §27 п. 9; ADR-010 |
| OCR-движки | движки и языковые пакеты RU/EN, потребность в GPU | `OI-008`; Итерация 2 | ADD §27 п. 3; ADR-010 |
| Embedding-модель | BGE-M3 или альтернатива, версия и revision | `OI-009`; Итерация 4 | ADD §27 п. 4; ADR-007 |
| Reranker | нужен ли отдельный multilingual reranker | `OI-010`; до retrieval evaluation | ADD §27 п. 5; ADR-007 |
| Gold-набор | состав первых пяти статей, включая RU/EN и сложные PDF | `OI-011`; Итерация 6 | ADD §27 п. 10; ADR-009 |

Закрытые вопросы из предыдущей редакции — неоднозначность retrieval-режима (ADR-007), выбор целевого
storage-бэкенда (ADR-006) и платформа локальной разработки (ADR-010) — здесь не дублируются.

## Как добавить ADR

Новый файл — `ADR-0NN-<краткое-имя>.md` со ровно шестью разделами (`## Контекст`, `## Решение`,
`## Статус`, `## Последствия`, `## Альтернативы`, `## Открытые риски`) и метаданными (`Статус`, `Дата`,
`Связанные требования ТЗ`). Изменение уже принятого решения оформляется новым ADR со ссылкой на
предыдущий, а не правкой старого: журнал — история, а не актуальная инструкция. Отложенное решение не
описывается как принятое; для него указывается владелец и этап закрытия.
