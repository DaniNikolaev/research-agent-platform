# ADR-009. Базовая линия зависимостей: Python, uv, группы и пиннинг

- **Статус:** Accepted
- **Дата:** 2026-11-11
- **Связанные требования ТЗ:** фиксированные версии стека; воспроизводимая установка; разделение
  runtime и опциональных групп
- **Связанные разделы ADD:** §19.1–§19.4, §22 (этап 0)

## Контекст

ADD §19.1 требует не доверять совместимости компонентов «по умолчанию», а собрать `pyproject.toml`,
разрешить зависимости через `uv lock`, проверить wheels на целевой ОС, выполнить smoke tests и
зафиксировать `uv.lock`. ADD §19.2 задаёт базовые линии на 11.11.2026. ADD §19.4 запрещает включать
необязательные библиотеки «на будущее».

Реализация: Python `3.13.18` (`.python-version`, `requires-python = ">=3.13.18,<3.14"`), пакетный
менеджер uv `0.13.7`, сборка hatchling, один `uv.lock` с 168 разрешёнными пакетами. Ядро
(`dependencies`): `pydantic==2.14.3`, `pyyaml==6.0.3`, `langgraph==1.2.20`, `langchain-core==1.8.0`.
Группы: `dev` (`pytest==9.2.0`, `pytest-cov==7.1.0`, `ruff==0.17.4`, `ty==0.0.101`,
`jsonschema==4.26.0`), `parsing` (`docling==2.150.0`, `pymupdf==2.1`), `storage` (`sqlalchemy==2.1.8`,
`alembic==1.20.1`, `psycopg[binary]==3.3.8`, `pgvector==0.5.1`), `api` (`fastapi==0.162.1`).

## Решение

1. **Точные версии, а не диапазоны.** Все зависимости закреплены через `==`: обновление — осознанное
   изменение `pyproject.toml` с последующим `uv lock`, а не следствие пересборки.
2. **Python 3.13.18 и верхняя граница `<3.14`.** Консервативная линия выбрана из-за риска бинарной
   несовместимости OCR/ML/PDF-зависимостей на Windows (ADD §19.3 п. 1); переход на 3.14 — отдельное
   решение после проверки wheels.
3. **Группы по назначению, а не по агентам.** `dev` — проверка; `parsing` — Docling/PyMuPDF;
   `storage` — SQLAlchemy/Alembic/psycopg/pgvector; `api` — FastAPI. Код Итерации 0 не импортирует ни
   одну из этих групп: `tests/unit/test_import_boundaries.py` запрещает `sqlalchemy`, `docling`,
   `pymupdf` в `domain` и `application`.
4. **`langchain` целиком не устанавливается.** Есть только `langchain-core==1.8.0`. Причина —
   ADD §19.3 п. 2: LangChain не должен становиться вторым оркестратором; LangGraph управляет
   процессом, а LangChain допустим лишь точечно для model integrations и structured output (внутри
   адаптера).
5. **`ty` — выбранный type checker.** `[tool.ty.src]` включает `src` и `tools` и исключает `tests`:
   контрактный набор намеренно конструирует невалидные payload'ы, чтобы доказать отказ валидации,
   поэтому типово-невалиден по замыслу. `ty check` проходит по `src` и `tools`. Линтер — `ruff`
   (`target-version = "py313"`, `line-length = 100`, набор `E,F,W,I,UP,B,C4,SIM,PT,RUF,ANN`).
6. **`pgvector` 0.5.1 — это Python-пакет, а не расширение PostgreSQL.** Пакет даёт типы SQLAlchemy и
   адаптер для передачи векторов; само расширение `vector` устанавливается в сервер PostgreSQL и имеет
   собственную версию — целевая 0.8.7 (ADD §19.2). Версии независимы: обновление Python-пакета не
   обновляет расширение в БД, и наоборот. Проверять нужно обе, а `CREATE EXTENSION vector` выполняется
   миграцией Alembic, а не установкой wheel.

## Статус

Accepted. `uv.lock` разрешён (168 пакетов) и проходит `uv lock --check`; тесты и `ty check`
выполняются на этой базовой линии. Изменение версии любой зависимости — правка этого ADR или ссылка на
новое решение.

## Последствия

Положительные: сборка воспроизводима на целевой машине; случайное «уплывание» версии невозможно;
группы позволяют ставить только нужное (`--group parsing`), не утяжеляя контрактный слой.

Цена: точные пины означают, что security-патч не приедет сам — нужен явный bump; 168 пакетов в lock
(включая транзитивные от `langgraph`) — заметный объём установки; `ty` версии 0.0.101 — pre-1.0
инструмент, его диагностика может меняться между выпусками.

## Альтернативы

- **Диапазоны версий (`>=`, `~=`).** Отклонено: воспроизводимость важнее удобства обновления,
  ADD §19.1 требует фиксации lock.
- **Poetry/pip-tools вместо uv.** Отклонено: ADD §19.2 фиксирует uv 0.13.7; uv даёт и lock, и запуск.
- **Pyright вместо `ty`.** Отклонено: ADD §19.2 допускает оба; выбран `ty` как совместимый с выбранным
  стеком и уже проходящий на `src` и `tools`.
- **Установить полный `langchain`.** Отклонено по ADD §19.3 п. 2 — риск второго оркестратора.

## Открытые риски

1. Wheels Docling 2.150.0 на Windows для Python 3.13.18 не проверены в этой итерации: `parsing`-группа
   не устанавливалась и не запускалась (ADD §19.1 требует smoke test до Итерации 2).
2. Версия расширения pgvector 0.8.7 в целевой среде не подтверждена: Python-пакет `pgvector==0.5.1` её
   не приносит, а образ PostgreSQL ещё не выбран (ADR-006, ADR-010).
3. Версия менеджера зафиксирована в `pyproject.toml` (`[tool.uv] required-version = "==0.13.7"`):
   другая версия `uv` откажется работать вместо тихого переразрешения зависимостей. Остаток риска:
   версия самого интерпретатора Python тоже управляется uv, поэтому первый `uv sync` на новой машине
   требует доступа к сети (managed CPython скачивается один раз).
4. Аудит уязвимостей зависимостей не настроен (нет `pip-audit` или аналога в группе `dev`); при точных
   пинах это означает, что уязвимая версия может оставаться в lock без сигнала.
