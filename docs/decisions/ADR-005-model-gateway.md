# ADR-005. Единый Model Gateway с явными capability

- **Статус:** Accepted (интерфейс) / Deferred (реальный адаптер)
- **Дата:** 2026-11-12
- **Связанные требования ТЗ:** единая точка доступа к моделям; запрет SDK провайдера в домене;
  структурированный вывод; отсутствие секретов в контрактах
- **Связанные разделы ADD:** §11.1–§11.5, §15, §19.3, §27 п. 1

## Контекст

ADD §11.1 требует единой точки доступа к generation, embeddings и reranking-моделям, ADD §11.3 —
capability smoke tests, ADD §11.4 — структурированный вывод и правило «успешный вызов не равен
успешной валидации». Провайдер не выбран; первый кандидат — DeepSeek V4.1 Flash 1017 через ранее
использованный внешний LLM-агрегатор, но его реквизиты и capability не подтверждены.

Интерфейс реализован полностью: `application/ports/model_gateway/types.py` (DTO), `errors.py`
(нормализованная иерархия), `protocols.py` (порты и `require_structured_output`). Адаптеров нет:
`platform/model_gateway/__init__.py` — дом с записанными требованиями, реальных вызовов не было.

## Решение

1. **Один gateway.** Любой доступ к моделям идёт через `ModelGatewayPort`; домен и агенты не
   импортируют SDK провайдера (проверяется AST-тестом, ADR-003).
2. **Явные capability.** `ModelCapabilities` (`provider_id`, `model_id`, `max_context_tokens`,
   `max_output_tokens`, `supports_structured_output`, `supports_json_schema`, `supports_streaming`,
   `supports_tool_calls`, `supports_embeddings`, `supports_reranking`, `json_schema_dialect`)
   проверяются **до** вызова. `require_structured_output()` падает с
   `ModelUnsupportedCapabilityError` до обращения к провайдеру.
3. **Нормализованные ошибки.** Каждый сбой переводится ровно в один класс: `ModelAuthError`,
   `ModelRateLimitError`, `ModelTimeoutError`, `ModelContextOverflowError`,
   `ModelUnsupportedCapabilityError`, `ModelMalformedResponseError`, `ModelProviderUnavailableError`,
   `ModelUnknownError`. `normalize_provider_error()` сохраняет уже нормализованную ошибку и
   сопоставляет типы от специфичного к общему.
4. **Retry и timeout принадлежат workflow.** Адаптер не повторяет, не спит и не выбирает
   fallback-модель; `timeout_seconds` едет внутри `ModelRequest`, повтор — новый запрос с новым
   `request_id`. Бюджеты заданы конфигурацией workflow, а не адаптером.
5. **Секреты не ходят в контракте.** У `ModelRequest` нет поля для credential; `metadata`
   (`dict[ShortStr, ShortStr]`, не более 16 ключей) отвергает ключи и значения, похожие на секрет.
   Аутентификация — забота адаптера через ссылку на секрет из composition root.
6. **Усечение не бывает молчаливым.** `finish_reason="length"` без хотя бы одного предупреждения в
   `warnings` — ошибка валидации `ModelResponse`. Ответ обязан нести `structured_payload`, `raw_text`
   или `raw_text_artifact`.

### Кандидат провайдера

DeepSeek V4.1 Flash 1017 через ранее использованный внешний LLM-агрегатор — **первый кандидат для
реального адаптера**, но не подтверждённый выбор. Точное имя агрегатора, протокол его API,
подтверждённый model id и набор capability **не задокументированы**; их нельзя выдумывать или
подставлять по аналогии. До подтверждения адаптер не пишется.

| Что подтвердить до написания адаптера | Зачем |
|---|---|
| chat/completions protocol | транспорт и формат запроса/ответа |
| structured output или JSON-Schema | путь структурированного извлечения |
| tool calling, если понадобится | сценарии workflow |
| максимальное окно контекста | бюджет и выбор режима (ADR-007) |
| максимальная длина вывода | бюджет и предупреждения об усечении |
| поведение при timeout | нормализация `ModelTimeoutError` |
| rate limits | retry-политика workflow |
| streaming | отмена и наблюдаемость |
| поведение reasoning-блоков | разбор ответа и `raw_text` |
| эффективный model id от провайдера | воспроизводимость `RunMetadata` |
| совместимость с DSH/LLM-инструментарием | рабочий процесс разработки |
| точное имя агрегатора и endpoint | конфигурация адаптера |

Ограничения: API-ключи не попадают в код, конфигурацию или отчёты; реальные вызовы на этом этапе не
выполняются; выбор провайдера не влияет на Domain, Application и LangGraph.

## Статус

Accepted для интерфейса: DTO, иерархия ошибок и порты реализованы и покрыты
`tests/unit/test_model_gateway.py`. Deferred для реального адаптера: провайдер, модели и профили
требуют подтверждения (OI-001–OI-005); Итерация 1 может использовать fake-адаптер.

## Последствия

Положительные: смена провайдера — новый адаптер, а не правка карточки или workflow; поведение при
ошибках предсказуемо для вызывающего кода; секрет не может попасть в лог через `request.redacted()`.
Кандидат сокращает неопределённость, но не заменяет capability smoke tests.

Цена: адаптер обязан транслировать ошибки и не имеет права на собственные повторы — backoff
перекладывается на workflow; `Protocol` не проверяется статически; расширение capability требует
правки DTO.

## Альтернативы

- **Прямые вызовы SDK из агентов.** Отклонено: нарушает ADD §11.1 и ADR-003, делает замену провайдера невозможной.
- **LangChain как основной слой абстракции.** Отклонено: скрывает capability, usage и finish reason,
  рискует стать вторым оркестратором (ADD §19.3 п. 2); точечные `langchain-core` интеграции допустимы.
- **Агрегатор как единственный провайдер.** Пока кандидат, а не решение: требует capability smoke
  tests и подтверждения реквизитов.

## Открытые риски

1. Кандидат DeepSeek V4.1 Flash 1017 не подтверждён: имя агрегатора, протокол, model id и capability
   неизвестны (OI-001–OI-005); smoke tests не проведены ни на одном endpoint.
2. `max_context_tokens`, поддержка JSON Schema и поведение при 429 подтверждены только типами.
3. Tokenizer не подключён: расчёт бюджета и режима retrieval (ADR-007) пока невозможен.
4. `ModelRequest` не несёт бюджет стоимости; учёт `TokenUsage.cost_usd` опционален, поэтому
   ограничение расходов не обеспечено контрактом.
