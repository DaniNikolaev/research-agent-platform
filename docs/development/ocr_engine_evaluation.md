# Оценка OCR-движков для Docling 2.150.0 (RU/EN, Windows 10, CPython 3.13)

**Статус:** исследование, **не решение** · **Открытый вопрос:** `OI-008` (владелец не выбрал движок) ·
**Итерация:** 2

> **Ничего не установлено и не скачано для OCR.** OCR выключен в конфигурации
> (`document_parsing.docling.do_ocr = false` принудительно, `ocr.enabled = false`), реализация
> `OcrEnginePort` отсутствует, ни один OCR-прогон не выполнялся. Всё, что ниже, — оценка по
> документации, по метаданным установленных пакетов и по коду Docling 2.150.0, а не по измерениям
> качества.

---

## 1. Что уже есть в окружении (проверено по файлам пакетов)

| Компонент | Наличие | Факт |
|---|---|---|
| `docling` 2.150.0 | установлен | лицензия `MIT` (`docling-2.150.0.dist-info`) |
| `docling-core` 2.106.0 | установлен | `MIT` |
| `rapidocr` 3.10.0 | **установлен** | лицензия `Apache-2.0`; приходит как зависимость Docling: `docling==2.150.0` требует `docling-slim[standard]`, а `standard` включает `rapidocr` (и `torch`/`torchvision`) |
| `onnxruntime` 1.31.1 | установлен | `MIT` |
| `torch` 2.15.0 / `torchvision` 0.29.2 | установлены | `Apache-2.0` и набор сторонних лицензий; ~484 MB / ~7 MB на диске |
| встроенные веса RapidOCR | **есть в wheel** | `PP-OCRv6_det_small.onnx` (9.5 MB), `PP-OCRv6_rec_small.onnx` (20.3 MB), `ch_ppocr_mobile_v2.0_cls_mobile.onnx` (0.6 MB) — всего ≈30.4 MB; лицензия весов `Apache-2.0` (PaddleOCR, см. `rapidocr-3.10.0.dist-info/licenses/MODEL_LICENSES.md`) |
| `tesserocr`, `easyocr`, `ocrmac` | **отсутствуют** | не устанавливались |
| Tesseract (системный бинарник), языковые пакеты | **отсутствуют** | не устанавливались |
| OCR-веса в кеше Hugging Face | **отсутствуют** | в `~/.cache/huggingface/hub` только два одобренных репозитория layout/table |

Важно: пакет `rapidocr` и его встроенные ONNX-веса появились в окружении **как зависимость
Docling**, а не как решение владельца. Наличие пакета не означает выбора движка: Docling с
`do_ocr = false` их не использует, `OcrEnginePort` не реализован, `ocr.enabled = false`.
Тем не менее при формулировке «ничего не скачивалось» нужно быть точным: ~30 MB весов RapidOCR
лежат на диске внутри wheel; отдельно OCR-веса не скачивались.

## 2. Как Docling 2.150.0 подключает OCR (по установленному пакету)

Проверено в `docling/datamodel/pipeline_options.py` установленной версии:

| Механизм | Значение |
|---|---|
| Виды движков (`OcrEngine`, устаревший enum; актуальный список — `get_ocr_factory().registered_kind`) | `auto`, `easyocr`, `tesseract_cli`, `tesseract`, `ocrmac`, `rapidocr` |
| Классы опций | `OcrAutoOptions`, `EasyOcrOptions`, `TesseractCliOcrOptions`, `TesseractOcrOptions`, `RapidOcrOptions`, `OcrMacOptions`, `NemotronOcrOptions`, `KserveV2OcrOptions` |
| Порядок авто-выбора (`OcrAutoOptions`) | `OcrMac` (macOS) → `Nemotron OCR` (Linux + CUDA) → `RapidOCR` с `onnxruntime` → `EasyOCR` → `RapidOCR` с `torch`; **Tesseract автоматически не выбирается** |
| Языки (`OcrOptions.lang`) | нативный код движка (`rus`, `ch`, `script/Cyrillic`) либо BCP-47 с префиксом `iso:` (`iso:ru` → `iso:ru-Cyrl`); язык без модели у выбранного движка — **ошибка**, а не тихий откат |
| Общие опции | `mode` (`default` / `full_page` / `layout_regions` / `pdf_aware_layout_regions`), `scale` (по умолчанию 3.0 → 216 DPI), `replace_broken_text_layer` |
| Бэкенды RapidOCR | `onnxruntime`, `openvino`, `paddle`, `torch` |
| Внешние плагины | `allow_external_plugins = false` по умолчанию |
| Веса | `artifacts_path` в `PipelineOptions` — каталог предзагруженных артефактов; `enable_remote_services = false` по умолчанию |

Наборы зависимостей (`docling-slim` 2.150.0): `standard` включает `rapidocr` + `torch` +
`torchvision`; отдельно есть `feat-ocr-rapidocr-onnx` (`rapidocr` + `onnxruntime`),
`feat-ocr-easyocr` (`easyocr` + `scikit-image`), `feat-ocr-tesserocr` (`tesserocr` + `pandas`),
`feat-ocr-mac` (`ocrmac`). `onnxruntime-gpu` ставится только отдельным extra
(`models-onnxruntime`) и в текущем окружении отсутствует.

### 2.1. Путь интеграции с платформой (два варианта, ни один не реализован)

| Вариант | Как | Что придётся изменить |
|---|---|---|
| A. Через Docling (`do_ocr = true`) | `DoclingParserOptions` + `PdfPipelineOptions` получают `ocr_options` выбранного движка; текст сканов приходит из Docling | снять запрет в `DoclingSettings` и в конструкторе `DoclingPdfParser`; заполнять `ParserProvenance.ocr_enabled = true` и `model_assets_revision`; добавить `engine_id` в `ocr`-секцию; заново зафиксировать `parser_options_hash`; проверить, как Docling отдаёт провенанс OCR-блока (страница/bbox) |
| B. Через `OcrEnginePort` | платформа сама рендерит страницы (`pymupdf` уже установлен) и вызывает движок; результат вливается в `ParsedDocument` | реализовать порт; добавить рендер страниц (сейчас `generate_picture_images = false`); определить, как OCR-текст получает `block_id`, `bbox` и статус страницы; скорее всего потребуется новая версия контракта `ParsedDocument` (появление `source = "ocr"` и `PageStatus`) |

Вариант A меньше кода, но отдаёт политику OCR библиотеке. Вариант B оставляет провенанс под
контролем платформы, но требует новых контрактных решений. Выбор — за владельцем вместе с `OI-008`.

## 3. Критерии сравнения

| Критерий | Почему важен |
|---|---|
| поддержка русского и английского | целевой корпус двуязычный |
| установка на Windows 10 + CPython 3.13 | целевая среда зафиксирована (ADR-010) |
| CPU/GPU | целевая машина без подтверждённого GPU |
| память | обработка идёт в одном процессе рядом с Docling |
| скорость | 500 страниц — верхняя граница; время на страницу определяет пригодность |
| размер весов | воспроизводимость установки и офлайн-развёртывание |
| лицензия | приватный продукт; лицензия должна допускать использование и распространение |
| офлайн-работа | платформа локальная; сетевые вызовы не приветствуются |
| путь интеграции | сколько кода и контрактных изменений требуется |

**Числа скорости, памяти и качества в этой таблице отсутствуют намеренно.** Ни один движок не
запускался, поэтому любые «страниц в секунду» были бы выдумкой. Измерения — задача после решения
владельца (§6).

## 4. Кандидаты

### 4.1. Tesseract (через `tesseract_cli` или `tesseract`)

| Свойство | Оценка |
|---|---|
| RU/EN | да, языковые пакеты `rus`, `eng` (tessdata); качество на русском зависит от набора (`fast`/`best`) |
| Установка на Windows 10 | внешний бинарник (установщик или пакетный менеджер), `PATH`; для `tesseract` (bindings) нужен `tesserocr` — колесо под CPython 3.13 **не проверено**, возможна сборка из исходников |
| CPU/GPU | только CPU |
| Память | не измерялась; по конструкции ниже, чем у torch-моделей |
| Скорость | не измерялась |
| Веса | языковые файлы tessdata; размер зависит от набора — не проверялся |
| Лицензия | Apache-2.0 (движок и официальный tessdata); конкретный набор данных требует проверки |
| Офлайн | да, полностью после установки |
| Интеграция | `TesseractCliOcrOptions` / `TesseractOcrOptions`; `tesseract` никогда не выбирается автоматически — нужен явный вид |
| Риски | внешняя зависимость вне Python-окружения; качество на сложной вёрстке и формулах не проверено |

### 4.2. RapidOCR (бэкенд `onnxruntime`)

| Свойство | Оценка |
|---|---|
| RU/EN | английский — уверенно; **русский не проверялся**: встроенные веса — компактные `PP-OCRv6` det/rec (происхождение PaddleOCR), наличие кириллицы в словаре распознавателя не подтверждено; для русского, вероятно, нужна отдельная rec-модель и словарь |
| Установка на Windows 10 | самый низкий риск: чистые Python-колёса (`rapidocr` + `onnxruntime`), системных зависимостей нет; пакеты уже стоят как зависимость Docling |
| CPU/GPU | CPU через `onnxruntime`; GPU — через `onnxruntime-gpu` (в окружении отсутствует) или бэкенд `torch` |
| Память | не измерялась; ONNX-инференс обычно экономнее torch-моделей |
| Скорость | не измерялась |
| Веса | ≈30.4 MB, уже на диске (внутри wheel), лицензия `Apache-2.0` |
| Лицензия | `Apache-2.0` (пакет и встроенные веса) |
| Офлайн | да, веса поставляются с пакетом |
| Интеграция | `RapidOcrOptions` (бэкенды `onnxruntime`/`openvino`/`paddle`/`torch`); для неподдерживаемого размера модели Docling поднимает `RapidOcrModelSizeNotSupportedError`, а не подменяет молча |
| Риски | русский язык и качество на научной вёрстке не подтверждены; смена rec-модели — отдельная задача с собственными весами и лицензией |

### 4.3. EasyOCR

| Свойство | Оценка |
|---|---|
| RU/EN | да, коды `ru`, `en`; заявлена широкая языковая поддержка |
| Установка на Windows 10 | `pip install easyocr` + `scikit-image`; `torch`/`torchvision` уже стоят — установка реальна, но добавляет зависимости |
| CPU/GPU | CPU работает; GPU — при CUDA-сборке torch (в окружении обычная сборка, CUDA не подтверждена) |
| Память | не измерялась; инициализация torch-моделей заметно тяжелее ONNX-варианта (не измерено) |
| Скорость | не измерялась; обычно медленнее ONNX-инференса (не проверено) |
| Веса | скачиваются при первом использовании в пользовательский каталог; размер зависит от языков — не проверялся |
| Лицензия | `Apache-2.0` для кода; лицензии распознающих моделей и детектора различаются и требуют отдельной проверки |
| Офлайн | да, после однократной загрузки весов; авто-загрузка конфликтует с политикой `model_assets.allow_auto_download = false` |
| Интеграция | `EasyOcrOptions`; языки передаются списком |
| Риски | автозагрузка весов, тяжёлые зависимости, неопределённые лицензии моделей |

### 4.4. Прочие варианты из перечисления Docling

| Движок | Почему не рассматривается сейчас |
|---|---|
| `ocrmac` (`OcrMacOptions`) | только macOS; на Windows 10 неприменим |
| `NemotronOcrOptions` | авто-выбор рассматривает его только на Linux с CUDA; поддержка Windows 10 и лицензия весов **не проверялись** |
| `KserveV2OcrOptions` | удалённый сервис: требует сети и внешнего компонента, что противоречит локальному характеру платформы |
| `auto` | выбирает то, что оказалось установлено на машине; результат разбора перестаёт быть воспроизводимым между машинами |

## 5. Краткий список (shortlist)

Порядок — по соотношению «риск установки на целевой Windows 10 / польза для RU», а не по
измеренному качеству.

1. **RapidOCR (onnxruntime).** Минимальный риск установки (чистые колёса, уже в окружении),
   офлайн, чистая лицензия `Apache-2.0`, лёгкие веса. Блокер: русский язык у встроенных весов не
   подтверждён — нужен замер и, вероятно, другая rec-модель.
2. **Tesseract (CLI).** Эталонная поддержка `rus`/`eng`, Apache-2.0, офлайн, без Python-зависимостей
   во время выполнения. Минусы: внешний бинарник и языковые пакеты, установка вне Python-окружения,
   качество на научной вёрстке неизвестно.
3. **EasyOCR.** Резерв, если первые два не дадут качества на русском. Минусы: тяжёлые веса,
   автозагрузка моделей, размытые лицензии моделей.

**Рекомендация — не решение.** Владелец не выбрал движок: `OI-008` открыт. Платформа обязана
оставаться в состоянии «OCR выключен, страницы помечаются `requires_ocr`», пока выбор не сделан и
не зафиксирован письменно. Оговорка по текущему поведению: полностью сканированный документ до
Quality Gate не доходит — пустой канонический текст отвергается узлом `build_canonical_document`
(код 1); вердикт `requires_ocr` достижим для смешанного документа (см.
[`document_parsing.md`](document_parsing.md) и [`quality_gate.md`](quality_gate.md)).

## 6. Вопросы владельцу

| № | Вопрос | Почему нельзя решить в коде |
|---|---|---|
| 1 | обязателен ли русский OCR в Итерации 3 или acceptable — только детекция | определяет объём работ и выбор движка |
| 2 | приоритет: минимальная установка (RapidOCR) или максимум качества на русском (Tesseract/EasyOCR) | компромисс «риск установки ↔ качество» |
| 3 | допустим ли GPU и есть ли он на целевой машине | влияет на `onnxruntime-gpu`/torch и требования к железу |
| 4 | допустима ли автоматическая загрузка весов при первом запуске | сейчас `allow_auto_download = false`; EasyOCR без предзагрузки не заработает |
| 5 | какие лицензии допустимы для весов OCR | EasyOCR-модели требуют отдельной проверки |
| 6 | кто и на каком наборе измеряет качество (CER/WER, время на страницу, память) | нужен gold-набор (`OI-011`) и методика |
| 7 | как OCR-текст получает провенанс (bbox/уверенность/`block_id`) | это контрактное решение, а не деталь адаптера |

## 7. План проверки (после решения, не выполнялся)

1. Набор: 5–10 страниц, покрывающих чистый скан, косой скан, две колонки, таблицу, формулы,
   русский и английский текст.
2. Метрики: CER/WER по эталонной расшифровке; время на страницу; пиковая память процесса;
   доля страниц, ушедших в `requires_ocr` ошибочно.
3. Условия: только офлайн, Windows 10, CPython 3.13.18, одинаковый DPI (`scale = 3.0`), один поток.
4. Фиксация результата: `engine_id`, версия, хеш весов, язык(и), `parser_options_hash` — иначе
   прогон невоспроизводим.
5. Критерий приёмки — за владельцем; платформа предоставит измерения, а не вывод «достаточно
   хорошо».
