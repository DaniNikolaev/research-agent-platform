# Dependency baseline и результаты разрешения зависимостей

**Дата:** 2026-11-12 · **Целевая среда:** Windows 10 Pro 22H2 (`10.0.19045`), x64 · **Lock-файл:** `uv.lock` (168 пакетов) · **Решение:** ADR-009

Документ фиксирует фактические версии, состав групп зависимостей и результаты проверок.
Он описывает **что реально проверено**, а что осталось непроверенным.

---

## 1. Инструменты

| Инструмент | Версия | Как получен |
|---|---|---|
| Python | `3.13.18` | установлен через `uv python install 3.13.18` (managed CPython, x86_64-pc-windows-msvc) |
| uv | `0.13.7` (`316c827e0`, 2026-11-03) | отдельное окружение инструментов; версия закреплена в `pyproject.toml` (`[tool.uv] required-version = "==0.13.7"`) |
| ОС | Windows 10 Pro 22H2, `10.0.19045`, x64 | — |

В системном `PATH` целевого Python `3.13.18` **не было** (доступны 3.14, 3.11, 3.10, 3.9),
поэтому версия установлена как managed-интерпретация uv. Это не подмена версии: в
`.python-version` зафиксировано `3.13.18`, и `uv` использует именно её.

Воспроизведение на чистой машине:

```powershell
uv python install 3.13.18
uv sync --locked          # core + dev
uv lock --check
```

## 2. Требование к версии Python

```toml
requires-python = ">=3.13.18,<3.14"
```

Причина верхней границы: 3.14 и 3.15 не проходили проверку колёс для OCR/ML/PDF-стека на
дату среза (ADD §19.3.1). Причина нижней: baseline ADD от 11.11.2026.

## 4. Решения по составу

1. **`langchain` целиком не устанавливается.** В lock присутствуют только
   `langchain-core`, `langchain-protocol`, `langgraph`, `langsmith`. Причина: LangChain
   не должен становиться вторым оркестратором (ADD §19.3.2); для structured output
   достаточно `langchain-core` и нужного integration-пакета, который появится вместе с
   выбранным провайдером.
2. **Провайдерские SDK не добавлены.** Провайдер — открытое решение заказчика
   (ADR-005, `Deferred`). Добавлять `openai`/`anthropic`/`langchain-*` «на будущий
   случай» запрещено ТЗ 0.10.
3. **`ty` выбран проверяющим типы** (а не Pyright): нативная интеграция с uv, не требует
   Node.js. Команда — `uv run ty check`; конфигурация в `[tool.ty.src]` ограничивает
   область `src` + `tools`, потому что контрактные тесты намеренно конструируют
   невалидные данные.
4. **Wildcard-версии не используются.** Все прямые зависимости зафиксированы точными
   версиями, транзитивные — `uv.lock`.
5. **`tenacity` не добавлен:** retry-политика принадлежит workflow и в Итерации 0 не
   реализуется; библиотека появится вместе с реализацией (если понадобится).

## 6. Ограничения и непроверенное

| Ограничение | Влияние | Что делать |
|---|---|---|
| `ty 0.0.101` — версия 0.0.x | возможны ложные срабатывания при обновлении минорной версии | зафиксировать версию в lock; обновлять осознанно вместе с ADR-009 |
| `pymupdf 2.1` — мажорная ветка 2.x | API отличается от 1.x legacy-проекта | учитывать при переписывании парсера (REIMPLEMENT, а не перенос) |
| Транзитивные зависимости не проверялись поштучно | 168 пакетов, часть — от `langgraph`/`docling` | принято lock-файлом; аудит безопасности — отдельная задача |
| Колёса parsing-группы весят гигабайты (`torch 2.15.0`, `transformers 5.22.2`) | окружение растёт; CI/новая машина качает это один раз | группа вынесена отдельно; устанавливается только для парсинга |

### 6.1. Результат контролируемой проверки parsing-группы (2026-11-12)

Выполнено:

```powershell
uv lock --check                     # exit 0, lock не менялся
uv sync --group parsing             # exit 0
uv run --group parsing python -c "import docling, pymupdf; print('PARSING_IMPORTS_OK')"
```

Факт: `PARSING_IMPORTS_OK`; `docling 2.150.0`, `pymupdf 2.1`, транзитивные
`torch 2.15.0`, `transformers 5.22.2`, `docling-core 2.106.0`, `docling-ibm-models 4.0.4`.

Что это подтверждает: для целевой среды Windows 10 x64 / CPython 3.13.18 существуют
подходящие колёса, установка и импорт работают. **Что это не подтверждает:** качество
парсинга, корректность извлечения таблиц и страниц, работу OCR (движки не выбирались,
модельные веса не скачивались, Tesseract не устанавливался). Вывод о качестве можно
делать только после Итерации 2 на реальном корпусе.

Побочный эффект: последующий `uv run` без `--group parsing` синхронизирует окружение по
умолчанию и может удалить эти пакеты. Для парсинга нужно повторно выполнять
`uv sync --group parsing`.

Отдельно: `pgvector` (Python) и `pgvector` (расширение PostgreSQL) имеют разные линейки
версий; в документации ADD указано расширение 0.8.7, в lock — Python-пакет 0.5.1. Это не
противоречие, но при развёртывании БД версия расширения фиксируется отдельно.
