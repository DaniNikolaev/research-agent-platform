# Приём документа (ingestion)

**Модули:** `application/services/document_ingestion.py`, `platform/documents/file_reader.py`,
`platform/document_parsing/txt/decoder.py`, `application/services/language_detection.py`,
`domain/documents/identity.py`, `domain/documents/models.py` · **Итерация:** 2

Приём — единственное место, где пользовательский файл превращается в состояние платформы. Порядок
шагов намеренный: каждый следующий опирается на предыдущий, а всё, что можно проверить до
сохранения, проверяется до него.

---

## 1. Шаги конвейера

```text
validate_input ──► initialize_run ──► ingest_source ──► inspect_document ──► …
(расширение)       (document_id,       (байты → хеш → оригинал → манифест)
                    run_id)
```

| № | Шаг | Что происходит | Ошибка при провале |
|---|---|---|---|
| 0 | `validate_input` | адаптер читает файл с ограничением размера и проверяет расширение по allow-list; запуск ещё не создан | `unsupported_format`, `source_not_found`, `source_not_readable`, `file_empty`, `file_too_large` |
| 1 | `initialize_run` (`probe_identity`) | читает файл, считает SHA-256 и выводит `document_id`/`source_sha256`; нужен, чтобы назвать запуск до его создания | `unsupported_format` |
| 2 | чтение источника | `SourceReaderPort.read` с `max_size_bytes`, проверка «регулярный файл, не ссылка», размер по метаданным до загрузки | `source_not_found`, `source_not_readable`, `file_empty`, `file_too_large` |
| 3 | allow-list расширений | `.pdf` и `.txt` только | `unsupported_format` |
| 4 | лимит размера по типу | 100 MB для PDF, 20 MB для TXT | `file_too_large` |
| 5 | сигнатура файла | PDF обязан начинаться с `%PDF-` (после ведущих пробельных байтов); TXT не должен содержать NUL в первых 4096 байтах | `invalid_file_signature` |
| 6 | хеш и идентичность | `sha256(data)`, `document_id = "doc_" + 24 hex` от доменно-разделённого кортежа | — |
| 7 | проверка коллизии | тот же `document_id` при другом содержимом — отказ | `document_identity_collision` |
| 8 | инспекция PDF | PyMuPDF: число страниц, шифрование, повреждение, лимит страниц | `pdf_corrupt`, `pdf_encrypted`, `pdf_empty`, `pdf_page_limit_exceeded` |
| 9 | декодирование TXT | детерминированный порядок кодеков; определение языка по тексту | `ValueError` декодера (см. §6) |
| 10 | сохранение оригинала | артефакт `original_document`, затем сверка sha256 с посчитанным | `source_integrity_error` |
| 11 | повторная проверка источника | файл перечитывается и хешируется заново; расхождение — отказ | `source_changed_during_ingestion` |
| 12 | манифест | `SourceDocumentManifest` сохраняется отдельным артефактом `handoff_package` | — |

Парсер **никогда не читает каталог пользователя**: он получает байты уже сохранённой неизменяемой
копии.

## 2. Лимиты

| Параметр (секция `document_ingestion`) | По умолчанию | Где применяется |
|---|---|---|
| `allowed_extensions` | `[".pdf", ".txt"]` | шаг 3; любые другие значения отвергаются валидацией конфигурации |
| `max_pdf_size_mb` | 100 | шаг 4 |
| `max_txt_size_mb` | 20 | шаг 4 |
| `max_pdf_pages` | 500 | шаг 8 (`pdf_page_limit_exceeded`) |
| `calculate_sha256` | `true` | **не читается кодом**: хеш считается всегда |
| `verify_source_unchanged` | `true` | шаг 11; при `false` повторная проверка пропускается |
| `MAX_DECODED_CHARS` (константа TXT-декодера) | 5 000 000 символов | шаг 9; больше — `ValueError` |

Тонкость: адаптер чтения получает «подсказку» размера, равную **максимальному** из лимитов
(100 MB), поэтому файл `.txt` размером, например, 50 MB будет прочитан в память и только затем
отвергнут по лимиту 20 MB. Это осознанный компромисс: адаптер чтения не знает тип файла до
получения расширения.

## 3. Идентичность документа

```text
document_id = "doc_" + SHA256("research-agent-platform/document/v1" + "|" + тип + "|" + sha256)[:24]
```

| Свойство | Следствие |
|---|---|
| зависит только от байтов и типа | переименование и перенос файла не меняют id |
| доменное разделение | id — не префикс файлового хеша; смена схемы версионируется строкой домена |
| тип входит в кортеж | PDF и TXT с одинаковыми байтами не сталкиваются |
| длина 24 hex (96 бит) | достаточно для адресации, компактно для URI и имён файлов |
| проверяется моделью | `DocumentIdentity` отвергает id, не соответствующий байтам: «идентичность — функция байтов и типа» |

## 4. Правило коллизии

Перед сохранением приём перечисляет артефакты документа (`list_for_document`):

* артефактов нет → продолжить;
* среди них есть артефакт с тем же `sha256` → это повторная обработка того же содержимого, продолжить;
* артефакты есть, но ни один не совпадает по `sha256` → **`document_identity_collision`**: два
  разных содержимого не сливаются под одним `document_id`.

Практический смысл: 24 hex — не криптографическая гарантия, а удобный адрес; коллизия должна
приводить к отказу, а не к тихой подмене оригинала.

## 5. Проверки целостности

| Проверка | Как выполняется | Что означает провал |
|---|---|---|
| хеш сохранённого оригинала | `ArtifactService.store_bytes` считает sha256 до записи, хранилище считает свой; сравнение | `source_integrity_error` — байты изменились на пути к диску |
| источник не изменился | `fingerprint()` (размер, mtime ns) + повторное чтение и повторный sha256 | `source_changed_during_ingestion` — файл менялся во время приёма |
| идентичность ↔ содержимое | валидатор `DocumentIdentity` | отказ ещё до записи |
| манифест ↔ артефакт | валидаторы `SourceDocumentManifest` (тип, `document_id`, `run_id`) | контракт не будет собран |
| неизменяемость | хранилище отвергает повтор `artifact_id` с другим содержимым | `ArtifactConflictError` вместо перезаписи |

Идемпотентность: повторная обработка того же файла в новом запуске создаёт **новые** артефакты с
новыми id (в id входит хвост `run_id`), а оригинал предыдущего запуска остаётся нетронутым.

## 6. Коды ошибок

Все ошибки ниже — `DocumentIngestionError` (стадия `registration`, `retryable = false`), кроме
явно отмеченных. CLI отображает их в код возврата **1**.

| Код | Условие | Где возникает |
|---|---|---|
| `source_not_found` | файла нет по указанному пути | адаптер чтения |
| `source_not_readable` | каталог, устройство, символьная ссылка, нет прав, ошибка `stat`/чтения | адаптер чтения |
| `unsupported_format` | расширение не входит в allow-list (в том числе файл без расширения) | `validate_input`, `probe_identity`, `ingest` |
| `file_empty` | размер 0 по метаданным или прочитано 0 байт | адаптер чтения |
| `file_too_large` | размер больше лимита: адаптера (100 MB) или по типу (100/20 MB) | адаптер чтения, `ingest` |
| `invalid_file_signature` | `.pdf` без `%PDF-`; `.txt` с NUL в первых 4096 байтах | `ingest` |
| `source_changed_during_ingestion` | файл изменился между чтением и проверкой; также при расхождении sha между `probe_identity` и `ingest` | `ingest`, узел `ingest_source` |
| `source_integrity_error` | хеш сохранённого оригинала не совпал с исходным | `ingest` |
| `document_identity_collision` | `document_id` уже существует для другого содержимого | `ingest` |
| `pdf_corrupt` | PyMuPDF не открывает файл или структура повреждена | `ingest` (`_inspect`) |
| `pdf_encrypted` | `needs_pass` или `is_encrypted` | `ingest` (`_inspect`) |
| `pdf_empty` | PDF сообщает 0 страниц | `ingest` (`_inspect`) |
| `pdf_page_limit_exceeded` | страниц больше `max_pdf_pages` | `ingest` (`_inspect`) |
| `text_encoding_error` | **объявлен, но не порождается** (см. ниже) | — |

Что важно знать про фактическое поведение:

* `text_encoding_error` (класс `UnsupportedEncodingError`) объявлен в
  `application/services/document_errors.py`, но **ни один код-путь его не поднимает**. Если ни один
  кодек не декодирует файл строго, декодер применяет `utf-8` с заменой символов и возвращает
  `encoding_uncertain = true` + число замен; документ принимается, а не отвергается. Пустой TXT и
  превышение `MAX_DECODED_CHARS` дают **`ValueError`** из адаптера декодера — не нормализованную
  ошибку пайплайна; CLI покажет её как общее исключение (код 1);
* `no PDF inspector is configured` использует код `document_ingestion_failed`, которого нет в
  перечне требований; попасть в эту ветку можно только при сборке конвейера без инспектора
  (в штатной сборке инспектор всегда есть).

## 7. Почему символьные ссылки отвергаются

`LocalSourceReader` отказывает символьной ссылке (`source_not_readable`) до чтения байтов:

* ссылка позволяет указать платформе на произвольный файл за пределами предполагаемого входа —
  ровно тот обход пути, который запрещён постановкой;
* после приёма оригинал копируется в хранилище, и «какой файл был на самом деле» перестаёт быть
  наблюдаемым; отказ на входе дешевле, чем разбор последствий;
* имя файла в манифесте — «голое», путь не сохраняется, поэтому сослаться на «тот же файл по
  ссылке» всё равно было бы нельзя.

Границы этой проверки, которые нужно знать:

| Случай | Поведение |
|---|---|
| символьная ссылка на файл (`is_symlink()`) | отвергается |
| каталог, в том числе junction/mount point | отвергается как «не регулярный файл» (`is_file()` — ложь) |
| жёсткая ссылка | **не отличима** от обычного файла: читается как обычный файл |
| файл, заменённый после `stat` до `read` | размер сверяется по фактически прочитанным байтам; подмена обнаруживается повторной проверкой (§5) |

## 8. Что приём не делает

* не распаковывает архивы и не поддерживает `.docx`, `.html`, `.rtf` — только `.pdf` и `.txt`;
* не парсит документ: страницы, блоки и таблицы появляются позже;
* не определяет язык по BOM: метод `bom_and_ratio` объявлен в контракте, но детектор его не
  возвращает;
* не удаляет и не «исправляет» исходный файл пользователя;
* не пишет в журнал содержимое документа (только идентификаторы, размер, хеш).
