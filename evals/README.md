# Evaluation (Итерация 6)

Каталог зарезервирован под измерение **качества извлечения**, а не корректности кода.
В Итерации 0 он пуст осознанно: без gold-набора любая метрика была бы декоративной.

---

## 1. Планируемое содержимое

```text
evals/
├── datasets/          исходные статьи (вне git: PDF не коммитятся)
├── gold_annotations/  эталонные значения, статусы, evidence и оценка поддержки
├── retrieval/         размеченные запросы и результаты Recall@K / MRR
└── reports/           отчёты прогонов evaluation
```

---

## 2. Требования к набору (ADD §18.2)

* не менее пяти реальных статей;
* русский и английский языки;
* обычный текстовый PDF, PDF с таблицами результатов, PDF с иной структурой;
* минимум один сложный/сканированный PDF для проверки OCR (отдельным этапом);
* по ключевым полям — gold annotation: значение, статус, evidence, страница и
  экспертная оценка смысловой поддержки;
* сомнительные случаи разрешает человек (adjudication).

Состав набора — открытое решение заказчика (ADR-010).

---

## 3. Метрики (ADD §18.3)

| Метрика | Что измеряет |
|---|---|
| Schema pass rate | доля результатов, прошедших типы и JSON Schema |
| Field accuracy | корректность значения против gold |
| Field coverage / recall | доля существенных сведений, не пропущенных системой |
| Evidence exactness | доля evidence, корректно разрешённых в исходнике |
| Evidence support precision | доля цитат, реально подтверждающих утверждение по оценке человека/1B |
| Unsupported claim rate | доля утверждений без достаточной опоры |
| False `not_found` rate | информация есть, но система заявила отсутствие |
| Retrieval Recall@K / MRR | качество retrieval на размеченных запросах |
| OCR CER / WER | ошибки распознавания |
| Cross-run consistency | стабильность при повторном запуске |
| Latency / cost per paper | время и стоимость обработки статьи |

Раздельная оценка по языкам обязательна (NFR-14).

---

## 4. Сравнение с legacy

Для каждой gold-статьи сохраняются оба результата: `legacy_run` и `v2_run`, оцениваемые
по одинаковым правилам (методика — `D:\MultiAgentPipeline\Agent1\Agent1A\tests\quality_checklist.md`,
переиспользуется как `REUSE_AS_REFERENCE`). Более новая система не считается лучше
только потому, что использует RAG или другой парсер (ADD §29.3).

---

## 5. Что уже сделано в Итерации 0 для будущего evaluation

* формат evidence позволяет проверить «есть ли цитата на странице» машинно
  (`match_status`), а «поддерживает ли она утверждение» — только вручную/через Agent 1B;
* в контрактах нет места для «красивых» чисел без evidence: `found` без ссылки не
  проходит валидацию;
* `not_found` нельзя назначить из-за пустого retrieval — правило зафиксировано в
  ADR-007 и в контракте состояния.
