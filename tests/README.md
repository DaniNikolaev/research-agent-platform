## 3. Принципы

1. **Тест ломает данные, а не модель.** Валидный документ — это `dict`; нарушение
   контракта выражается изменением `dict`, как это сделал бы сломанный продюсер.
2. **Никаких реальных внешних систем.** Ни API-ключей, ни сети, ни БД, ни OCR-весов,
   ни LLM-вызовов. Fake-адаптеры детерминированы.
3. **Контракт проверяется дважды.** Pydantic и независимый `jsonschema` по
   закоммиченной схеме: это ловит расхождение «модель vs опубликованная схема».
4. **Архитектура — тоже тест.** Направления зависимостей проверяются AST-сканом, а не
   только ревью.
5. **Тест не должен зависеть от порядка.** Модули не мутируют глобальное состояние
   (в отличие от legacy-набора, где подменялся глобальный `PROJECT_ROOT`).

## 4. Что тестами не покрыто (и почему)

* реальное качество извлечения — требует gold-набора и ручной разметки (Итерация 6);
* парсинг/OCR — не реализованы;
* поведение реального провайдера — провайдер не выбран;
* нагрузка и производительность — вне объёма Итерации 0;
* миграция v1→v2 — реализован только интерфейс и правила, поэтому проверяется отказ
  при отсутствии провенанса, а не сам перенос.
